> 版本：v1.0　编写日期：2026-11-25　状态：待确认
> 原则：每个选型都给出"为什么选它 / 为什么不选替代 / 本机实测版本"，版本号均来自 2026-11-25 实测可获取的版本。

## 一、后端

### 1.1 Spring Boot 3.5.16

| 项 | 说明 |
| --- | --- |
| 选定版本 | **3.5.16**（实测 `repo.maven.apache.org` 上 3.5.x 最新为 3.5.16） |
| 为什么不用 4.x | 本地 m2 虽有 4.0.0/4.0.3/4.0.5，但 MyBatis-Plus、knife4j 等生态对 Boot 4 的适配未验证。需求明确"如采用 4.x 必须先验证第三方依赖兼容性"，验证成本 > 收益 |
| 为什么不用 3.2/3.3 | PMS 用 3.2，但 Hub 是新项目，无历史包袱；3.5 是当前 LTS 主线，JDK 21 一等支持 |
| 风险 | 私有仓库 `nexus` 镜像 `mirrorOf=*` 会拦截中央仓库，需确认 10.7.0.185:8081 已代理 3.5.16；本地 m2 已有 3.5.16 目录，说明曾下载过 → 低风险 |

### 1.2 JDK 21（LTS）

- 需求指定。apt 候选 `21.0.13.1+2-1~24.04.1`。
- **双 JDK 共存策略**：Hub 编译与运行用 21；执行引擎为 PMS 类项目注入 17。
  - `update-alternatives` 让系统默认 `java` = 21（满足 Hub）。
  - `hub_project.jdk_version=17` 时，`hub-runtime` 显式设置 `JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64` 且 `PATH` 前置其 `bin`。
  - 任务日志首行打印 `java -version` 实际输出，便于事后排查"串味"。

### 1.3 MyBatis-Plus 3.5.18

- 实测 `mybatis-plus-spring-boot3-starter` release = **3.5.18**。
- 选它而非 JPA：需求指定；且团队既有项目（PMS）就是 MP，代码风格一致，Agent 生成代码的准确率更高。
- 分页用 `PaginationInnerInterceptor`，乐观锁用 `OptimisticLockerInnerInterceptor`（任务状态机依赖它）。

### 1.4 其他后端依赖

| 依赖 | 用途 | 备注 |
| --- | --- | --- |
| Spring Security 6.x | 认证授权 | 随 Boot 3.5 管理版本 |
| jjwt 0.12.x | JWT | 与 PMS 风格一致，但独立密钥 |
| Redisson 3.4x | 分布式锁 / 信号量 | 比手写 SETNX 可靠，带看门狗 |
| springdoc-openapi 2.x | 接口文档 | 不用 knife4j（其对 Boot 3.5 的适配滞后） |
| Jackson | JSON | 内置 |
| Spring Validation | 参数校验 | 内置 |
| Flyway 10.x | 数据库版本管理 | 见下 |

### 1.5 数据库脚本策略：Flyway 而非手工 SQL

需求要求"数据库脚本必须可重复初始化"。

- 选 **Flyway**：`V1__init_schema.sql`、`V2__...` 顺序执行，`flyway_schema_history` 保证幂等。
- 同时保留 `database/init/00_clean.sql`（仅 dev，drop & create database）方便重置。
- 不选 Liquibase：XML 冗长，Agent 生成易错。

## 三、Agent 通信协议：ACP 优先 + 三适配器

### 3.1 决策

| 方案 | 评价 |
| --- | --- |
| **ACP（stdio JSON-RPC）** | ✅ 主路线。结构化事件流（思考/工具调用/文件变更/权限请求），可精确做审批拦截；Claude/Codex/OpenCode 均支持 |
| CLI（`claude -p --output-format stream-json`） | ⚠️ 降级路线。每消息一进程，冷启动 5~15 s，会话续接靠 `--resume`，事件语义弱于 ACP |
| HTTP（OpenAI 兼容） | ✅ 用于 WeClaw 反向接入与未来远程 Agent；对本地编码 Agent 不适用（无文件系统能力） |
| 直接 PTY + 屏幕抓取 | ❌ 脆弱，语义全靠文本猜测，无法做细粒度审批 |

### 3.2 ACP 客户端自研（重要工作量项）

**事实**：Maven Central 检索 `agent-client-protocol`、`acp-java`、`agentclientprotocol` 均为 **0 条**。无官方 Java SDK。

**方案**：在 `hub-agent` 内实现精简 ACP 客户端。

| 组成 | 实现 |
| --- | --- |
| 传输 | `ProcessBuilder` 启子进程，stdin/stdout 上按 `\n` 分隔的 JSON-RPC 2.0（NDJSON）；stderr 单独收为诊断日志 |
| 报文 | Jackson `JsonNode` 手写编解码（不引入未经验证的第三方 ACP 库） |
| 客户端→Agent 方法 | `initialize`、`authenticate`、`session/new`、`session/load`、`session/prompt`、`session/cancel` |
| Agent→客户端 通知 | `session/update`（增量消息、工具调用、计划、可用命令） |
| Agent→客户端 请求 | `session/request_permission`（审批闸门）、`fs/read_text_file`、`fs/write_text_file` |
| 版本协商 | `initialize` 返回 `protocolVersion` + `agentCapabilities`，落库用于能力画像 |
| 并发 | 单 session 串行 prompt；多 session 各自独立进程或用 `sessionId` 复用 |
| 超时 | 每次 JSON-RPC 请求带超时；`session/prompt` 无响应即判空闲超时 |

**参考实现对照**（只读学习协议语义，不复制代码）：`@agentclientprotocol/sdk` 2.12.0、`@agentclientprotocol/claude-agent-acp` 0.112.0、`@zed-industries/codex-acp` 0.16.0。

**风险**：协议仍在演进（R3）。对策是只依赖上述稳定方法集，能力协商失败即降级到 CLI 适配器并记录原因。

### 3.3 各 Agent 的启动命令（实测确认）

| Agent | ACP 启动 | 来源 |
| --- | --- | --- |
| Claude Code | `claude-agent-acp`（npm `@agentclientprotocol/claude-agent-acp` 0.112.0） | 实测 bin 名 |
| Codex | `codex-acp`（npm `@zed-industries/codex-acp` 0.16.0，或 `codex-acp` 1.11.0） | 实测 bin 名 |
| OpenCode | `opencode acp` | 官方文档 + 实测包 `opencode-ai` 1.19.6 |

这些命令**写进 `agent_registry` 的配置字段**，不硬编码在 Java 里，便于版本升级后调整。

## 四、微信接入：WeClaw（Tespera 分支）

| 项 | 结论 |
| --- | --- |
| 仓库 | `https://github.com/Tespera/weclaw`，MIT，fastclaw-ai/weclaw 的维护分支（上游 2026-04 起停更） |
| 版本 | 最新 Release **v0.10.1** |
| 构建 | Go，**要求 1.25+**；本机无 Go → 优先用 Release 二进制 |
| 运行形态 | 单二进制，`weclaw start` 后台常驻；Linux 下用 systemd 自管 |
| 与 Hub 的入站 | HTTP 模式 = OpenAI 兼容 Chat Completions → 配 `type:"http"`, `endpoint:"http://127.0.0.1:18080/v1/chat/completions"`, `api_key` |
| 与 Hub 的出站 | `POST http://127.0.0.1:18011/api/send` `{to, text, media}`；`WECLAW_API_ADDR` 可调 |
| 媒体回传 | `media` 支持 URL 或绝对本地路径；本地路径仅接受 loopback 调用者 |
| 未验证 | HTTP 模式请求体是否携带稳定发送者 ID（R1，第六阶段首日验证） |

**为什么不用 weclaw-proxy 之类第三方**：需求指定 WeClaw；且多一层代理会掩盖问题。

### 4.1 合规与风险声明（必须在交付文档中保留）

- 微信个人号 Bot 走 iLink 非官方协议，**存在账号被风控/限制的风险**。
- 使用闲置微信号，不与主账号混用。
- 仅对白名单用户提供服务，不做群发、不用于营销、不联系人外发。
- 若腾讯调整协议导致不可用，Hub 侧无需改动（只换渠道适配器）。

## 五、存储

| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 关系库 | MySQL 8.0（本地 WSL 独立实例，库 `ai_hub`） | 需求指定；不共用 PMS 的 `10.7.0.185` |
| 缓存/队列/锁 | Redis 7.x（本地，db 0 缓存 / db 1 队列） | 需求指定 |
| 日志文件 | 本地文件系统 `~/ai-hub/logs` | 大日志不塞 DB |
| 记忆 | Markdown + MySQL（第一期） | 需求指定；`MemoryRetriever` 预留向量检索接口 |
| 对象存储 | 不引入 | 附件走本地目录 + 静态映射 |

**字符集**：`utf8mb4` / `utf8mb4_0900_ai_ci`（MySQL 8 默认，比 `utf8mb4_unicode_ci` 更准）。
**时区**：连接参数 `serverTimezone=Asia/Shanghai`，DB 内 `DATETIME(3)` 存本地时间（与 PMS 习惯一致，避免团队认知负担）。

## 六、可观测性

| 关注点 | 方案 |
| --- | --- |
| 日志 | Logback，JSON 结构化（便于后续接入采集），按天 + 100 MB 滚动，保留 30 天 |
| 审计 | 独立表 `hub_audit_log`，AOP 切面自动落库，业务代码不侵入 |
| 监控 | Spring Boot Actuator + 自建 `hub-monitor` 聚合接口（不引入 Prometheus/Grafana，第一期过度） |
| 实时推送 | SSE（管理后台任务详情页、Agent 状态页）；不用 WebSocket，SSE 更简单且够用 |
| 链路追踪 | 第一期不引入；跨 Agent 调用用 `traceId`（雪花 ID 派生）串日志即可 |

## 九、被否决的选项汇总

| 选项 | 否决理由 |
| --- | --- |
| Spring Boot 4.x | 生态适配未验证，需求要求先验证，成本高收益低 |
| GraalVM Native Image | 反射多（MyBatis/Jackson），调试困难，启动快 3 s 不值得 |
| 微服务拆分 | 需求明确"模块化单体"；单机部署拆分反而增加运维成本 |
| gRPC 内部通信 | 模块在同一 JVM，进程内调用即可 |
| WebSocket | SSE 满足单向推送，且穿透代理更简单 |
| 直接操作微信协议自研桥 | 逆向成本高、合规风险大；WeClaw 已解决 |
| Docker 执行 Agent | 需求明令禁止隔离副本执行 |
| pnpm / yarn | 本机未装，多一个工具多一处失败点 |
| Knife4j | 对 Boot 3.5 支持滞后，改用 springdoc |
| 向量数据库（第一期） | 需求写明"后期可引入" |
