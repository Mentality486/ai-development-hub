# 数据库设计

> 版本：v1.0　编写日期：2026-11-25　状态：待确认
> 目标库：MySQL 8.0　库名：`ai_hub`　字符集：`utf8mb4` / `utf8mb4_0900_ai_ci`
> 脚本落位：`database/migration/V*.sql`（Flyway），初始化入口 `database/init/00_clean.sql`

---

## 一、总体约定

| 约定 | 内容 | 理由 |
| --- | --- | --- |
| 主键 | `BIGINT UNSIGNED` 雪花 ID（MyBatis-Plus `ASSIGN_ID`） | 单机可生成、趋势递增、不暴露业务量、便于未来分库 |
| 业务编号 | 对人可见的 `xxx_no`，如 `TASK-10001`，`CHAR(20)` 唯一 | 微信里报编号比报雪花 ID 友好（需求示例即 `TASK-10001`） |
| 时间字段 | `created_at` / `updated_at` 全表必备，`DATETIME(3)` 默认 `CURRENT_TIMESTAMP(3)`，`updated_at` 加 `ON UPDATE` | 与 PMS 习惯一致，毫秒精度够排查 |
| 逻辑删除 | 仅对用户可删除的实体（project/identity/memory）加 `deleted_at`；任务与日志**永不物理删除也永不逻辑删除** | 审计需要 |
| 状态字段 | `VARCHAR(32)` + 应用层枚举（不用 MySQL ENUM） | ENUM 加值需 DDL，且 MyBatis-Plus 映射麻烦 |
| 布尔 | `TINYINT(1)` | — |
| 金额/成本 | `DECIMAL(12,4)` | 记录 token 成本 |
| 索引命名 | `idx_表名_字段`、`uk_表名_字段` | 便于运维定位 |
| 外键 | **不建物理外键**，靠应用层 + 索引保证 | 便于数据修复与分表；PMS 同样约定 |
| 大字段 | 单字段 >8 KB 的日志/报文，存文件，DB 存路径 | 需求"大体积日志独立存储" |

### 状态枚举落地

任务状态、Agent 状态等在 Java `enum` 定义，DB 只存 code。为避免"DB 里出现应用不认识的字符串"，每个枚举表配套一条字典（见 `sys_dict` 可选表，第一期用 Java 枚举 + 注释，不建字典表）。

## 四、索引与性能设计要点

| 场景 | 设计 |
| --- | --- |
| 任务列表分页 | `idx_task_status_time` 覆盖 `WHERE status=? ORDER BY created_at DESC` |
| 任务详情多次查询 step/log | 均以 `task_id` 前导列建索引 |
| Agent 心跳扫描 | `idx_agent_heartbeat`，定时任务 `WHERE last_heartbeat_at < ?` |
| 记忆检索 | 第一期 `LIKE` + `ft_mem_content` ngram 全文索引；后续换向量 |
| 会话列表 | `idx_conv_user_time` |
| 审计按天查 | `idx_audit_time`，按月分区可选（第二期） |
| 防全表扫 | 所有列表接口强制分页，默认 20，上限 200 |

### 容量估算（保守）

| 表 | 日均增量 | 一年 | 处置 |
| --- | --- | --- | --- |
| hub_task | 20 | ~7 300 | 无需处置 |
| hub_task_log | 2 000 | ~73 万 | 单行 <1 KB，约 700 MB，可接受 |
| hub_message | 500 | ~18 万 | 单行平均 0.5 KB |
| hub_audit_log | 1 000 | ~37 万 | 只增不删，预留 2 GB |
| 任务日志文件 | 200 MB/月 | 2.4 GB | 保留 90 天，脚本清理 |

## 五、Flyway 脚本规划

```
database/
├── init/
│   └── 00_clean.sql              -- 仅 dev：DROP DATABASE IF EXISTS ai_hub
├── migration/
│   ├── V1__sys_auth.sql          -- sys_user/role/permission/关联 + 内置数据
│   ├── V2__hub_identity_channel.sql -- hub_identity/conversation/message/channel/channel_session/channel_message

│   ├── V5__task.sql              -- hub_task/step/task_agent/task_log
│   ├── V6__approval_memory.sql   -- hub_approval/hub_memory

```

规则：
1. 已合并的 `V*.sql` **永不修改**，改结构一律新增 `V{n+1}__xxx.sql`。
2. 每个脚本必须可重复执行到"空库 → 最新"的任意起点（每条 `CREATE TABLE IF NOT EXISTS`）。
3. `00_clean.sql` 只在 dev profile 允许执行，prod 启动时若检测到该文件被调用则直接失败。
