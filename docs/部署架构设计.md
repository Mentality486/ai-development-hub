## 一、部署拓扑

```
Windows 11 宿主
├── WSL2 虚拟机（Ubuntu-24.04）
│   │
│   ├─ systemd（PID 1，实测 running）
│   │   ├── mysql.service            127.0.0.1:3306   库 ai_hub
│   │   ├── redis-server.service     127.0.0.1:6379
│   │   ├── ai-hub-server.service    127.0.0.1:18080  （Java 21）
│   │   ├── ai-hub-web.service       127.0.0.1:15173  （生产：静态托管或 nginx）
│   │   └── weclaw.service           127.0.0.1:18011  （第六阶段）
│   │
│   ├─ systemd --user 实例（Linger=yes，实测可用）
│   │   └── 上述服务的 user 级单元（推荐）
│   │
│   └─ 文件系统 /home/wangchong/
│       ├── projects/ai-development-hub/   源码（Git 仓库）
│       ├── projects/mgiot-pms/            被管理的目标项目
│       └── ai-hub/                        运行时根
│           ├── projects/   指向 sources 的软链
│           ├── worktrees/  任务隔离区
│           ├── logs/       应用与任务日志
│           ├── identity/   AI 人格 Markdown
│           ├── config/     运行期配置（不进 Git）
│           └── runtime/    pid、锁、临时文件
```

> **不做端口反向代理到外网的默认配置。** 需要远程访问时用 SSH 隧道，不用 `netsh portproxy` 暴露公网。

## 二、端口规划

| 服务 | 端口 | 绑定 | 说明 |
| --- | --- | --- | --- |
| Hub API | 18080 | 127.0.0.1 | 避开 PMS 8010 与常见 8080 |
| 前端 dev | 15173 | 0.0.0.0（dev 期） | 避开 PMS 3000 与 Vite 5173 |
| 前端 prod | 由 Hub 静态托管 18080/app 或 nginx 15174 | | 首选 Hub 内嵌托管，少一个进程 |
| WeClaw 本地 API | 18011 | 127.0.0.1 | WeClaw 默认值，不改 |
| MySQL | 3306 | 127.0.0.1 | 不对外 |
| Redis | 6379 | 127.0.0.1 | 不对外 |

已确认：8080/8010/5173/3306/6379 当前**全部空闲**，18080/15173/18011 未占用。

## 三、环境准备清单（一次性的）

```bash
# 1. 系统包
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk mysql-server redis-server jq unzip git-lfs

# 2. JDK 21 设为默认（Hub 用）
sudo update-alternatives --set java  /usr/lib/jvm/java-21-openjdk-amd64/bin/java
sudo update-alternatives --set javac /usr/lib/jvm/java-21-openjdk-amd64/bin/javac
java -version   # 期望 21.x

# 3. MySQL 初始化
sudo mysql_secure_installation
sudo mysql -e "CREATE DATABASE IF NOT EXISTS ai_hub DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
sudo mysql -e "CREATE USER IF NOT EXISTS 'ai_hub'@'localhost' IDENTIFIED BY '<强密码>';"
sudo mysql -e "GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,INDEX,DROP,REFERENCES ON ai_hub.* TO 'ai_hub'@'localhost';"
sudo mysql -e "FLUSH PRIVILEGES;"

# 4. Redis 加固
sudo sed -i 's/^# requirepass .*/requirepass <强密码>/' /etc/redis/redis.conf
sudo sed -i 's/^bind .*/bind 127.0.0.1 ::1/' /etc/redis/redis.conf
sudo systemctl restart redis-server
redis-cli -a <强密码> ping   # PONG

# 5. Git 身份（当前为空，必须配）
git config --global user.name  "AI Hub"
git config --global user.email "ai-hub@localhost"

# 6. 运行时目录
mkdir -p ~/ai-hub/{projects,worktrees,logs,identity,config,runtime}
chmod 700 ~/ai-hub
```

**启动时强校验**：`prod` profile 下若检测到任一必填项等于 `change-me*` 或为空 → 直接 `exit(1)` 并打印缺失键名（不打印值）。

### 4.3 双 JDK 的处理

`application.yml` 中不写死 JDK。执行引擎读取 `hub_project.jdk_version`：

```yaml
hub:
  runtime:
    jdk:
      default: "21"
      homes:
        "17": /usr/lib/jvm/java-17-openjdk-amd64
        "21": /usr/lib/jvm/java-21-openjdk-amd64
```

任务启动时按项目选择，并在日志首行打印实际 `JAVA_HOME` 与 `java -version`。

## 五、systemd 单元

### 5.1 推荐用 user 级（免 root，与本机 `Linger=yes` 契合）

`~/.config/systemd/user/ai-hub-server.service`

```ini
[Unit]
Description=AI Development Hub Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/home/wangchong/projects/ai-development-hub
EnvironmentFile=/home/wangchong/ai-hub/config/.env
Environment="SPRING_PROFILES_ACTIVE=prod"
ExecStart=/usr/lib/jvm/java-21-openjdk-amd64/bin/java \
  -Xms512m -Xmx1536m \
  -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
  -Duser.timezone=Asia/Shanghai \
  -Dfile.encoding=UTF-8 \
  -jar /home/wangchong/ai-development-hub/hub-server/target/hub-server.jar
Restart=on-failure
RestartSec=5
SuccessExitStatus=143
StandardOutput=append:/home/wangchong/ai-hub/logs/server.out
StandardError=append:/home/wangchong/ai-hub/logs/server.err

[Install]
WantedBy=default.target
```

`weclaw.service`

```ini
[Unit]
Description=WeClaw WeChat Bridge
After=network-online.target

[Service]
Type=simple
Environment="WECLAW_API_ADDR=127.0.0.1:18011"
ExecStart=/home/wangchong/.local/bin/weclaw start --foreground
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

启用：
```bash
systemctl --user daemon-reload
systemctl --user enable --now ai-hub-server.service
loginctl enable-linger wangchong   # 已为 yes，仍显式设置以防新环境
```

### 5.2 备选：system 级

若 user 级在 WSL 上不稳定（WSL 关闭后 user 实例可能不自动拉起），改用 `/etc/systemd/system/`，加 `User=wangchong`。两种单元文件内容几乎相同，`install-service.sh` 用参数切换。

## 六、部署脚本

| 脚本 | 职责 |
| --- | --- |
| `deploy/start.sh` | 检查环境 → 启动 mysql/redis → 启动 hub-server → 启动 weclaw（可选） → 健康检查 |
| `deploy/stop.sh` | 逆序停止，优雅关闭（先 SIGTERM，10 s 后 SIGKILL） |
| `deploy/status.sh` | 逐服务状态 + 端口监听 + Actuator health + 微信连接状态 |
| `deploy/install-service.sh` | 生成并安装 systemd 单元（`--user` / `--system`），`enable --now` |
| `deploy/uninstall-service.sh` | 停用并移除单元，保留数据 |
| `deploy/backup.sh` | `mysqldump` + 保留 7 天 |
| `deploy/README.md` | 操作手册 |

### start.sh 关键行为

```bash
#!/usr/bin/env bash
set -euo pipefail

HUB_HOME="${HUB_HOME:-$HOME/ai-hub}"
JAR="$HUB_HOME/../projects/ai-development-hub/hub-server/target/hub-server.jar"

# 1. 前置检查
[ -f "$HUB_HOME/config/.env" ] || { echo "缺少 .env"; exit 1; }
[ -f "$JAR" ] || { echo "缺少 jar，请先 mvn package"; exit 1; }
java -version 2>&1 | grep -q 'version "21' || { echo "JDK 不是 21"; exit 1; }

# 2. 依赖服务
systemctl is-active --quiet mysql || sudo systemctl start mysql
systemctl is-active --quiet redis-server || sudo systemctl start redis-server

# 3. 应用
systemctl --user restart ai-hub-server
for i in $(seq 1 60); do
  curl -sf localhost:18080/actuator/health >/dev/null && { echo "Hub 已就绪"; break; }
  sleep 1
  [ "$i" = 60 ] && { echo "启动超时"; journalctl --user -u ai-hub-server -n 50; exit 1; }
done
```

## 七、启动顺序与依赖

```
mysql (需要) ──┐
redis (需要) ──┼──▶ ai-hub-server ──▶ (可选) weclaw
               │         │
               └─────────┴──▶ 静态前端（由 Hub 托管时无独立进程）
```

Hub 启动自检（`ApplicationRunner`）：
1. DB 连通 + Flyway 迁移完成（失败即退出）。
2. Redis `ping`（失败即退出，队列与锁依赖它）。
3. `~/ai-hub` 子目录存在且可写（失败则自动创建，权限不足即退出）。
4. Agent 发现（**异步**，不阻塞启动；失败只告警）。
5. 渠道连接（若启用，**异步**）。
6. 孤儿任务对账（RUNNING 但无进程 → 标记 FAILED）。

## 八、WSL 特殊性处理

| 问题 | 处理 |
| --- | --- |
| WSL 关闭后服务停止 | systemd + `Linger=yes`；Windows 启动 WSL 后自动拉起。可选 Windows 任务计划 `wsl.exe -d Ubuntu-24.04 -u wangchong -- bash -lc "systemctl --user start ai-hub-server"` |
| WSL 内网 IP 每次重启会变 | 服务全部绑 `127.0.0.1`，浏览器用 `localhost`（WSL2 自动转发），不依赖固定 IP |
| 时间漂移（休眠唤醒后） | systemd-timesyncd；Hub 记录任务时长用 `Instant`/`Duration` 而非挂钟差 |
| 内存回收（`.wslconfig`） | 建议 `[wsl2] memory=12GB swap=4GB`；Hub 堆上限 1.5 GB，Maven/Node 构建可吃 2–3 GB |
| `/mnt/*` 性能差 | 代码与构建全部在 `~/` 下；实测提醒：9p 文件系统权限语义不同，容易出 EACCES |
| Windows 路径混入 | `PathGuard` 直接拒绝 `/mnt/*` 与 `\\wsl*`，从源头杜绝 |
| 宿主重启后 Docker 容器不自动起 | 本项目不依赖 Docker（Agent 必须在 Native 跑）；MySQL/Redis 用系统包而非容器 |

## 九、升级与回滚

### 升级
```bash
cd ~/projects/ai-development-hub
git pull --ff-only
mvn -T 1C clean package -DskipTests
# Flyway 在启动时自动迁移（先备份！）
deploy/backup.sh && systemctl --user restart ai-hub-server
```

### 回滚
```bash
git checkout <上一个 tag>
mvn -T 1C clean package -DskipTests
# 若 DB 已迁移：用备份恢复
mysql -uai_hub -p ai_hub < ~/ai-hub/backup/ai_hub-YYYYMMDD.sql
systemctl --user restart ai-hub-server
```
**规则**：Flyway 迁移脚本不提供 undo（社区版无此功能），回滚靠备份恢复。因此每次 `V*.sql` 前必须备份。

## 十一、两套 profile 差异

| 项 | dev | prod |
| --- | --- | --- |
| 前端 | Vite dev server 15173 + HMR | 构建产物由 Hub 托管 |
| 数据库 | `ai_hub`（可随时 `00_clean.sql` 重置） | `ai_hub`（禁重置，Flyway 只前滚） |
| Flyway | `clean` 允许 | 禁用，且启动时校验 checksum |
| 日志级别 | DEBUG（`hub.*`） | INFO |
| SQL 打印 | 开 | 关 |
| Swagger | 开 | 关（或需 ADMIN 且只读） |
| 密钥校验 | 宽松（可用 change-me） | 严格（等于 change-me 即拒绝启动） |
| Agent 超时 | 10 min | 60 min |
